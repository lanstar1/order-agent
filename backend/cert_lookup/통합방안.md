# 통합방안 — `lanstar-cs-assistant` 상담 시스템 + `cert_lookup`

기존 상담 챗봇은 **제품이 무엇인지**에 답한다. `cert_lookup` 은 **그 제품의 근거서류가
무엇인지**에 답한다. 두 질문은 근거 데이터도 다르고 틀렸을 때의 손해도 다르다
(전자는 오안내, 후자는 **없는 인증서를 있다고 답하는 사고**). 그래서 통합의 핵심은
"합치는 것"이 아니라 **어디서 갈라지고 어디서만 만나는지를 고정하는 것**이다.

| 항목 | 결론 |
|---|---|
| 접점 | **새 0단계 라우터**. 인증 의도면 기존 1·2단계를 **건너뛴다**(병렬 아님) |
| 모델명 추출 | 기존 정규식을 `cert_lookup.resolver.extract_models` 로 **교체** + 사전 폴백 |
| 제품 마스터 연동 | **조건부 부착, 기본 off**. 화이트리스트 5개 필드만 |
| 공급사 요청 초안 | 텍스트/파일로만 산출. **SMTP 코드를 붙이지 않는다** |
| 배포 | 사내 FastAPI 1대. 동기화 PC = 즉시 / 서버 = 드라이브 API 필수 |

## 1. 기존 2단계 구조와의 접점

### 1-1. 어디에 들어가는가 — 0단계 라우터

```
                       고객/사내 문의
                            │
                    ┌───────▼────────┐
                    │ 0단계 의도 분기 │  ← 신설. 룰 기반(LLM 아님)
                    └───┬────────┬───┘
             인증/자료 요청       그 외
                    │            │
        ┌───────────▼──────┐  ┌──▼────────────────┐
        │ cert_lookup      │  │ 1단계 상담이력 검색 │
        │ POST /ask        │  └──┬────────────────┘
        │ (KB 가 유일 근거) │     │ 미스
        └───────────┬──────┘  ┌──▼────────────────┐
                    │         │ 2단계 제품분석 LLM │
                    │         └──┬────────────────┘
                    └────────────┴──► 응답
```

**병렬 도구로 두면 안 되는 이유** — 세 가지 다 실측 근거가 있다.

1. **1단계가 오답을 만든다.** 상담이력 검색은 유사 질문 매칭이다. "RoHS 주세요"는
   모델이 달라도 문장이 거의 같아서, 다른 모델의 과거 답변("네, 첨부드립니다")이
   최상위로 올라온다. 자료 보유 여부는 모델마다 다르므로 이건 구조적 오답이다.
2. **2단계가 없는 자료를 만든다.** 제품 마스터의 `소구점`·`재질`에 "RoHS 인증",
   "UL 인증" 문구가 들어있는데, 같은 모델의 KB coverage 가 `X` 인 조합이
   **실측 109건**(README 기준 엄격 집계 62건) 있다. LLM 컨텍스트에 둘 다 넣으면
   "없는 자료를 만들어내지 않는다"는 절대 규칙이 그 자리에서 깨진다.
3. **주의문구가 소실된다.** `O*`/`자재*`/스캔문서 주의문구는 `policy.py` 가 강제하는
   것인데, LLM 이 요약하는 순간 사라지거나 완화된다.

따라서 **인증 경로에 들어오면 KB 가 유일한 근거**다. `/ask` 의 `answer` 문자열을
LLM 이 다시 쓰지 않고 **그대로 내보낸다**. LLM 은 인사말·문장 다듬기 정도만 허용하고,
`notices[]` 는 **한 글자도 바꾸지 않는다**.

### 1-2. 의도 감지 규칙

자료유형 토큰 탐지는 **재구현하지 않는다** — `cert_lookup.cli.detect_doc_types()` 가
별칭 사전(`search.DOC_TYPE_ALIASES`)과 모델 토큰 제거(`_strip_models`)까지 이미 한다.
0단계가 할 일은 그 결과에 **요청 동사구**와 **부정 신호**를 겹쳐 라우팅을 정하는 것뿐이다.

| 급 | 신호 | 예시 토큰 | 단독으로 라우팅? |
|---|---|---|---|
| **A. 자료유형** | `detect_doc_types()` 히트 | RoHS·로하스·유해물질 / CE·CE인증서 / REACH·리치 / MSDS·SDS·물질안전보건자료 / PFAS / UL / Fluke·플루크·채널테스트·전송성능 / CoC·원산지증명서 / 시험성적서 / 도면·CAD / 매뉴얼 | **예** (단 `Data sheet` 는 예외, 아래 A′) |
| **A′. 사양서 계열** | 데이터시트·사양서·규격서·스펙·제품사양 | — | **B 신호가 함께 있을 때만**. 없으면 기존 2단계(사양 질문) |
| **A″. KC** | KC(단어경계)·적합등록·적합인증·전파인증·방송통신기자재·필증 | — | **예** (KC 인덱스는 별도 조회 경로) |
| **B. 요청 동사구** | 인증서·증명서·서류·자료·첨부·파일·양식·보내주·주세요·요청·제출·발행 | — | 아니오. **모델명 + B** 일 때 라우팅 |
| **C. 부정 신호** | 반품·교환·환불·배송·재고·가격·단가·견적·AS·불량·설치·연결 안 됨 | — | A 가 없으면 기존 경로 |

```python
# chatbot/cert_router.py — 0단계. 판단만 하고 답변은 만들지 않는다.
from cert_lookup import cli as cert_cli

REQUEST_WORDS = ('인증서', '증명서', '서류', '자료', '첨부', '파일', '양식',
                 '보내주', '보내 주', '주세요', '요청', '제출', '발행', '있나요', '있어요')
NEGATIVE_WORDS = ('반품', '교환', '환불', '배송', '재고', '가격', '단가', '견적',
                  'AS', '불량', '고장', '안 돼', '안돼', '설치 방법', '사용법')
SPEC_ONLY = {'Data sheet'}          # 사양서 계열은 요청 동사구가 있어야 자료 경로

def route(message: str) -> dict:
    p = cert_cli.parse_message(message)          # 모델·자료유형·의도를 한 번에
    has_req = any(w in message for w in REQUEST_WORDS)
    has_neg = any(w in message for w in NEGATIVE_WORDS)
    types = set(p.doc_types)

    if p.intent == 'kc':                                   # A″
        hit = True
    elif types - SPEC_ONLY:                                # A
        hit = True
    elif types & SPEC_ONLY:                                # A′
        hit = has_req
    else:                                                  # B
        hit = bool(p.model) and has_req and not has_neg

    if hit and has_neg and not (types - SPEC_ONLY) and p.intent != 'kc':
        hit = False                                        # C 우선(A 없을 때만)
    return {'route': 'cert' if hit else 'legacy', 'parsed': p.as_dict()}
```

동작 확인용 실제 문장:

| 문장 | 판정 | 근거 |
|---|---|---|
| `LS-6UTPD-3MG RoHS 인증서 주세요` | cert | A(RoHS) |
| `LS-1600HQ CE 있나요?` | cert | A(CE) |
| `LS-OVERC 적합등록필증 들어있나요` | cert(KC) | A″ |
| `LS-HDAOC 시험성적서 보내주세요` | cert | A(Test report) |
| `LS-7UTP 뭐뭐 있어?` | cert | B + `intent=coverage` |
| `LS-HDMI21 스펙 어때요?` | **legacy** | A′ 만, 요청 동사구 없음 → 제품분석이 더 낫다 |
| `LS-HDMI21 데이터시트 파일 주세요` | cert | A′ + B |
| `이 케이블 불량인데 교환되나요` | legacy | C |
| `LS-6UTPD 견적 주세요` | legacy | B∩C, A 없음 |

**혼합 문의**("3M짜리 재고 있어요? RoHS도 같이 주세요")는 두 경로를 **각각 태워 응답을
섹션으로 분리**한다. 근거를 한 문단에 섞지 않는 것이 규칙이다.

### 1-3. 되묻기·미발견의 세션 처리

`/ask` 는 되묻기와 미발견을 **에러로 내지 않는다**(HTTP 200). 0단계는 이걸 대화 상태로
받아야 한다.

```python
r = requests.post(f'{CERT_API}/ask', json={'message': msg, 'mode': 'internal'}).json()
if r['needs_clarification']:
    session['pending_cert'] = {'doc_type': r['data'].get('parsed', {}).get('doc_type'),
                               'candidates': r['candidates']}
    return r['answer']                       # "어느 제품군인지 알려주십시오" + 후보
# 다음 턴: 사용자가 후보 하나를 고르면 override_model 로 재질의
```

`kind` 별 처리는 `ambiguous`(제품군 다중) / `need_model`(모델 미추출) / `not_found`
(`suggestions[]` 로 "혹시 이 모델인가요?") 세 가지다.

## 2. 모델명 추출 통합

### 2-1. 기존 정규식의 실측 간극

기존 `r'(LS[P]?-[A-Za-z0-9\-\.]+)'` 로 제품군 키 427개를 훑으면 **45개를 온전히 잡지
못한다.** 내역은 이렇다.

| 유형 | 건수 | 예 | 실제 위험 |
|---|---|---|---|
| `LSN-` 접두 | 19 | `LSN-BOOT-COVER-WN`, `LSN-CAT6-STP` | **높음.** 사용자가 그대로 입력하는 실판매 모델인데 **한 글자도 매칭되지 않는다** |
| 비-LS 모델 | 3 | `DP12MM-10M`, `OM4-LCLC`, `USB2.0-AMAF-S1M` | **높음.** 동일 |
| 범위·와일드카드 표기 | 23 | `LS-6AFTP-0.5M,1M,2M,…`, `LS-HDMT-0.3M~5M`, `LS-FMD / LS-FMP` | 낮음. KB 내부 표기이고 앞부분이 잡혀 `resolve()` 가 흡수한다 |

KC 모델 118개는 기존 정규식으로 **전건 매칭**된다(전부 `LS-` 접두).

### 2-2. 1차 — 정규식을 교체한다

`cert_lookup.resolver.MODEL_RX` 가 기존 패턴의 상위집합이다. `LS-`/`LSP-` 는 그대로
잡히므로 **하위호환이 깨지지 않는다.**

```python
# 변경 전 (SKILL.md)
def extract_model_names(text):
    return [m.upper() for m in re.findall(r'(LS[P]?-[A-Za-z0-9\-\.]+)', text, re.I)]

# 변경 후 — 정규화(대소문자/언더스코어/접두 하이픈 누락)까지 포함된다
from cert_lookup.resolver import extract_models
extract_models('ls_6utpd 3mg 로하스')    # ['LS-6UTPD']
extract_models('LSN-CAT6-STP RoHS')      # ['LSN-CAT6-STP']
extract_models('DP12MM-10M CE')          # ['DP12MM-10M']
```

`MODEL_RX` 가 추가로 담는 분기는 `LSN-`, `DP\d+MM-\d+M`, `OM[34]-…`, `USB\d(\.\d)?-…`
넷이다. `USB` 분기는 **하이픈을 필수**로 둬서 "USB 3.0 케이블 주세요"의 일반명사를 모델로
오인하지 않는다.

### 2-3. 2차 — 사전(gazetteer) 폴백

정규식 확장만으로는 **앞으로 추가될 비-LS 모델**을 따라가지 못한다(공급사가 자기 형번을
그대로 쓰는 품목이 계속 들어온다). 정규식이 0건일 때만 KB 이름 사전으로 최장일치 스캔을
한다. 사전은 `family_keys 427 + members + kc_models 118`을 합친 것이고
`KnowledgeBase.all_model_names()` 로 이미 만들어져 있다.

```python
# chatbot/cert_router.py (이어서)
import re
from cert_lookup import loader, resolver

_GAZ = None

def _gazetteer():
    global _GAZ
    if _GAZ is None:
        kb = loader.load_kb()
        names = set(kb.all_model_names()) | set(kb.kc_models)
        names = {n for n in names if not loader.WILDCARD_MEMBER.search(n) and len(n) >= 5}
        _GAZ = sorted(names, key=len, reverse=True)      # 최장일치
    return _GAZ

def extract_models_robust(text: str) -> list[str]:
    hits = resolver.extract_models(text)
    if hits:
        return hits
    up = re.sub(r'[_\s]+', '-', (text or '').upper())
    out = []
    for name in _gazetteer():
        i = up.find(name)
        if i < 0:
            continue
        before = up[i - 1] if i else ' '
        after = up[i + len(name)] if i + len(name) < len(up) else ' '
        if before.isalnum() or after.isalnum():
            continue                                     # 부분어 오탐 차단
        out.append(name)
        if len(out) >= 3:
            break
    return out
```

비용은 미스 경로에서만 발생하는 문자열 탐색 800여 회로, 사내 트래픽에서는 무시할 수준이다.
사전은 manifest 재로딩 시 함께 비워야 한다(6장 참조).

### 2-4. 두 인덱스의 우선순위

모델명 하나가 **마스터에는 있고 KB 에는 없거나**(예: KC 전용 모델 `LS-OVERC` 는 인증자료
제품군에 없다) 그 반대일 수 있다. 경로별로 조회 대상이 다르다는 것을 명시해 둔다.

| 경로 | 조회 함수 | 미스일 때 |
|---|---|---|
| legacy(상담) | `find_model_in_master()` | 접두 매칭 → 유사 모델 제안 |
| cert(인증) | `search.lookup()` → 내부에서 `resolve_all()` | 제품군 미스면 **KC 인덱스로 자동 폴백**, 그래도 없으면 `suggestions[]` |

`cert_lookup` 쪽은 이미 두 인덱스를 함께 본다(`/lookup` 이 `res.cert.found == False` 이고
KC 가 색인돼 있으면 KC 응답으로 넘어간다). 챗봇이 별도 분기를 짤 필요는 없다.

## 3. 제품 마스터 연동 (선택기능 7) — 권고와 근거

### 권고: **조건부 부착, 기본 off.** 인증 응답의 근거로는 절대 쓰지 않는다.

붙이지 않는 쪽이 기본인 이유는 하나다. 제품 마스터의 `제품분석`은 **제품 이미지를 LLM 이
해석한 결과**이고, 그 안의 인증 문구는 **검증되지 않은 마케팅 문장**이다. KB coverage 와
정면 충돌하는 조합이 실측된다.

```
LS-6IC-UK      제품분석 소구점: "RoHS … KC 인증"   KB coverage: RoHS=X, CE=X
LS-6UTP-300MGN 제품분석 소구점: "UL 인증 … RoHS"   KB coverage: RoHS=자재, CE=X
LS-BOOT-CR7    제품분석 소구점: "RoHS … KC 인증"   KB coverage: RoHS=X, CE=X
```

제품 마스터 2,039개 중 제품군 로직으로 KB 에 연결되는 것이 **597개**, 그중 인증 문구가
coverage 와 충돌하는 것이 **109개(18%)** 다. 다섯 번에 한 번 틀리는 근거는 근거가 아니다.

### 붙여도 되는 조건 — 세 개를 **모두** 만족할 때

| # | 조건 | 이유 |
|---|---|---|
| 1 | 질문이 **사양 질의**를 겸할 때 (`doc_type == 'Data sheet'` 또는 A′ 경로) | RoHS·CE 요청에 사양을 덧붙일 이유가 없다 |
| 2 | cert 응답이 `found == true` **그리고** `confident == true` | `prefix` 추정 매칭에 사양까지 얹으면 오답이 두 배가 된다 |
| 3 | 주입 필드가 **화이트리스트** 안일 것 | 아래 |

```python
SPEC_WHITELIST = ('제품유형', '포트구성', '주요사양', '사용방법', '사용용도')
SPEC_BLOCKLIST = ('소구점', '재질', '외형')     # 인증·마케팅 문구가 섞여 있다
```

`소구점`·`재질`을 뺀 것이 이 권고의 전부다. 충돌 109건은 전부 이 두 필드에서 나온다.
(`외형`은 인증과 무관하지만 색상 오안내를 만들어 함께 뺀다.)

### 부착 형태 — 라벨을 분리한다

```
랜스타입니다. LS-6UTPD-3MG(제품군 LS-6UTPD) 사양서 안내드립니다.
· [문서명] / 발급기관 / 문서번호 / 발급일
※ 공급사가 발행한 사양서이며 제3자 인증서가 아닙니다.

── 참고: 제품 사양 (사내 제품분석 데이터 · 인증 근거 아님) ─────────
· 제품유형: Cat.6 UTP 다이렉트 패치코드
· 주요사양: …
```

구분선과 라벨을 반드시 유지한다. 이 블록의 문장은 **고객사 제출 근거로 인용될 수 없다**는
것이 라벨의 역할이다.

### 반대 방향 — legacy 경로가 인증을 말하려 할 때

기존 2단계 LLM 응답에 인증 관련 문장이 섞이면(고객이 사양을 묻다가 "RoHS 되죠?"로 넘어가는
전형적 흐름) **그 문장만 잘라내고 cert_lookup 결과로 대체**한다. 인증 주장에 대한 단일
진실원천은 KB 다.

```python
CERT_CLAIM_RX = re.compile(r'RoHS|REACH|CE\s?인증|KC\s?인증|UL\s?인증|친환경 인증', re.I)
if CERT_CLAIM_RX.search(llm_answer):
    llm_answer = CERT_CLAIM_RX.sub('[인증 항목]', llm_answer)
    llm_answer += '\n\n' + cert_ask(f'{model} 인증 보유현황')['answer']
```

## 4. 공급사 요청 초안 생성 (선택기능 8)

### 4-1. 절대 규칙

* **발송하지 않는다.** 이 기능의 코드 경로에 SMTP·메일 API 호출을 **넣지 않는다**.
  넣어두고 "쓰지 않는다"로 관리하면 언젠가 호출된다.
* 산출물은 **텍스트뿐**이다. `POST /draft/supplier-request` → `{subject, body_en,
  internal_note, checklist}`. 담당자가 복사해 자기 메일 클라이언트에서 보낸다.
* 초안 하단에 **"이 초안은 자동 발송되지 않습니다. 담당자가 검토 후 직접 발송하십시오."**
  를 고정 문구로 붙인다.
* `mode=customer` 에서는 이 엔드포인트를 **호출하지 않는다**(사내 공급사 정보 노출).

### 4-2. 트리거와 공급사 결정

| 트리거 | 조건 |
|---|---|
| 미보유 | `coverage[doc_type] == 'X'` |
| 자재 누락 | `material_missing` 이 비어 있지 않음 (예: LS-HDAOC RoHS = 절연 미확보) |
| 만료 | `expired == true` (갱신본 요청) |

공급사는 **해당 제품군이 이미 보유한 문서의 `sources[].sender` 최빈값**으로 정한다.
실측 결과 **427개 제품군 전부**에서 발신인이 확인되므로 "공급사를 모르겠다" 분기는 없다.

```python
def supplier_of(family_rec, kb):
    from collections import Counter
    c = Counter()
    for d in family_rec.get('documents') or []:
        did = d.get('doc_id') if isinstance(d, dict) else d
        for s in (kb.docs.get(did) or {}).get('sources') or []:
            if s.get('sender'):
                c[s['sender']] += 1
    return c.most_common(1)[0][0] if c else None
```

## 5. 배포 아키텍처

### 5-1. 두 실행 환경의 차이

```
[사내 브라우저/챗봇] ──HTTP──> [FastAPI :8080] ──┬── manifest 3종 (저장소, 12MB, 메모리)
                                                 └── 파일 실체 1,074건 (1.0GB)
                                                      ├─ 동기화 폴더 → local_path
                                                      └─ 드라이브 API → api_link
```

| 항목 | 드라이브 동기화 PC | 서버 (NAS / Render) |
|---|---|---|
| 파일 해석 | `local_path` (현재 전건 성공) | **`api_link` 필수**. 자격증명 없으면 `folder_fallback` 로 떨어져 폴더 URL 만 안내 |
| 필요 디스크 | 1.0GB (동기화본) | 12MB (manifest 만) |
| 가동 시간 | PC 가 켜져 있을 때만 | 상시 |
| 파일 최신성 | 동기화 지연만큼 | 즉시 |
| CORS | `*` 로 둬도 무방 | **반드시 좁힌다** (`CERT_KB_CORS_ORIGINS`) |
| 접근 통제 | PC 방화벽 | 사내 IP 화이트리스트 또는 리버스 프록시 인증 필수 |
| 권고 | 시범 운영·검증 | 정식 운영 |

**NAS(사내 10.0.0.152) 배포가 Render 보다 낫다.** 이유 두 가지: (1) 사내 전용 자료라
외부 노출 자체가 리스크이고, (2) 시놀로지 Cloud Sync 로 드라이브를 동기화하면 **자격증명
없이 `local_path` 경로를 그대로 유지**할 수 있다. Render 를 쓴다면 파일시스템이 휘발성이라
드라이브 API 가 **선택이 아니라 필수**다.

```bash
# 서버 공통 기동
export CERT_KB_REPO=/opt/lanstar-cert-kb
export CERT_KB_CORS_ORIGINS='http://10.0.0.152:3000,http://chat.lanstar.local'
uvicorn cert_lookup.api:app --host 0.0.0.0 --port 8080 --workers 2
```

워커 수만큼 manifest 가 메모리에 올라간다(워커당 수십 MB). 사내 트래픽에는 2 로 충분하다.

### 5-2. 드라이브 API 자격증명 설정 — 단계별

**서비스 계정**을 쓴다. OAuth 사용자 토큰은 만료·재동의가 있어 무인 서버에 맞지 않는다.

1. **GCP 프로젝트 준비** — console.cloud.google.com 에서 프로젝트 생성(또는 기존 선택).
2. **Drive API 활성화** — `APIs & Services → Library → Google Drive API → Enable`.
3. **서비스 계정 생성** — `IAM & Admin → Service Accounts → Create`.
   이름 예: `cert-kb-reader`. 역할 부여는 **불필요**(드라이브 권한은 공유로 준다).
4. **키 발급** — 해당 계정 → `Keys → Add key → JSON`. 내려받은 파일이 자격증명이다.
5. **드라이브 폴더 공유** — 서비스 계정 이메일
   (`cert-kb-reader@<project>.iam.gserviceaccount.com`)에게 **뷰어**로 공유한다.
   루트 `랜스타_인증자료`(`1_MpX-bxWIvFuS1u8CM2rhUjdU9SbRKm1`) 하나만 공유해도 하위가
   상속되지만, 확실히 하려면 4개 폴더를 개별 공유한다.

   | 폴더 | ID |
   |---|---|
   | 문서 | `1UqdvlWWvhBIXUAkaFZLzsRYUJi6b66Ii` |
   | KC | `1bZ0BJv3HOiXp9yjROAJ7i5L5LPzDDbYf` |
   | _미확정 | `11bp2bgzxD5p0crEythRLCvYlHhCsD3iF` |
   | KC_필증PDF만 | `1Tev66aFBUvkFD5VA_Qb_hieRvZatsso8` |

6. **서버에 키 배치** — 저장소 밖에 두고 권한을 잠근다.
   ```bash
   install -m 600 /path/sa.json /etc/lanstar/cert-kb-sa.json
   export GOOGLE_APPLICATION_CREDENTIALS=/etc/lanstar/cert-kb-sa.json
   ```
7. **라이브러리 설치** — `pip install google-api-python-client google-auth google-auth-oauthlib`
   (없으면 조용히 로컬 폴백으로 내려간다).
8. **검증 — 이 단계를 건너뛰면 안 된다.** 자격증명이 잘못돼도 **예외가 나지 않고 폴백**
   하므로, 성공 여부는 `status` 로만 확인할 수 있다.
   ```bash
   curl -s localhost:8080/health | python3 -m json.tool     # drive.api_credentials == true
   curl -s localhost:8080/file/b5728b739902 | python3 -m json.tool
   #   file.status == "api_link"  → 성공
   #   file.status == "folder_fallback" → 공유 누락 또는 파일명 불일치
   ```

**함정 두 가지.**
* 서비스 계정으로 만든 링크는 **그 계정이 볼 수 있는 링크**다. 사내 담당자가 자기
  구글 계정으로 열려면 원본 폴더가 사내 계정에 공유돼 있어야 한다. 사내 전용 도구이므로
  현재 구성으로 충분하지만, **고객에게 링크를 그대로 전달하면 열리지 않는다** —
  고객 전달은 파일 다운로드 후 첨부, 또는 별도 공유 설정이 원칙이다.
* 서비스 계정 키는 사실상 영구 비밀이다. **저장소·챗봇 설정·로그에 절대 넣지 않는다.**

## 6. 운영 주의사항

### 6-1. manifest 갱신 시 재로딩

`loader.load_kb()` 는 **모듈 레벨 캐시**다(`loader._CACHE`). manifest 파일을 바꿔도
**돌고 있는 프로세스는 옛 데이터를 계속 답한다.**

* 가장 안전한 방법은 **프로세스 재기동**이다. 인덱스 로드는 수 초면 끝난다.
* 무중단이 필요하면 관리 엔드포인트를 만들되, **캐시가 세 곳**이라는 점을 놓치면 안 된다.

```python
@app.post('/admin/reload')          # 사내망 + 공유 토큰 뒤에 둘 것
def reload_kb(token: str = Header(...)):
    if token != os.environ['CERT_KB_ADMIN_TOKEN']:
        raise HTTPException(403)
    kb = loader.load_kb(force=True)   # ① manifest 캐시
    cli._drive_cache = None           # ② 드라이브 리졸버(동기화 루트 탐색 결과)
    cert_router._GAZ = None           # ③ 2-3 의 사전
    cli.drive_resolver(kb)
    app.state.kb = kb
    return {'ok': True, 'counts': {'documents': len(kb.docs), 'families': len(kb.families)}}
```

재로딩 후 `python3 -m cert_lookup.cli --selftest` 와 `tests/test_cert_lookup.py` 를
돌려 8개 필수 케이스가 그대로인지 확인한다. **기대값이 바뀌었다면 데이터가 바뀐 것이므로
테스트를 고치기 전에 왜 바뀌었는지부터 확인한다.**

### 6-2. 드라이브 파일 교체 시 영향

manifest 에는 **file ID 가 없다**(재업로드하면 바뀌므로). 파일은 `folder_id + filename`
으로 찾는다. 결과적으로 **파일명이 링크의 키**다.

| 드라이브에서 한 일 | 결과 |
|---|---|
| 같은 이름으로 덮어쓰기(드라이브 버전 관리) | **영향 없음.** 권장 방식 |
| 파일명 변경 | `folder_fallback` 으로 강등 — 폴더 URL 만 안내됨 |
| 다른 폴더로 이동 | 동일하게 `folder_fallback` |
| 파일 삭제 | `missing` |
| 내용만 교체(같은 이름) | 링크는 정상이나 **manifest 의 `sha1`/`size_bytes`/`pages`/`issue_date` 가 낡는다** |

운영 규칙 세 줄로 요약된다.

1. 파일 교체는 **같은 이름으로 덮어쓰기**를 원칙으로 한다.
2. 이름을 바꿔야 하면 manifest 의 `drive.filename`·`original_filename`·`sha1`·
   `size_bytes` 를 **같이** 고친다.
3. `status == folder_fallback` 건수가 늘어나면 원인은 거의 항상 파일명 변경이다.
   주간 점검 스크립트로 전건 해석을 돌려 카운트를 본다.

```bash
python3 - <<'EOF'
from cert_lookup import loader, cli
kb = loader.load_kb(); r = cli.drive_resolver(kb)
from collections import Counter
c = Counter(r.resolve_document(rec).status for rec in kb.docs.values())
print(c)      # local_path/api_link 외의 값이 있으면 조사한다
EOF
```

### 6-3. 신규 자료 추가 파이프라인 연결점

수집 파이프라인은 `파이프라인/step1_survey.py … step12_final.py` 이고 산출물은
`제품인증자료/manifest.jsonl`(step12 의 283행) 과 `manifest_family.jsonl`(408행) 이다.
`cert_lookup` 은 이 두 파일과 `KC적합등록자료/manifest.jsonl`, `RoHS요청이력.csv`,
`drive_folders.json` 다섯 개만 읽는다. **CSV 파생물은 읽지 않으므로** 재생성 순서에
얽매이지 않는다.

신규 자료가 들어올 때 확인할 접점.

| 접점 | 확인 사항 |
|---|---|
| 새 `doc_type` 등장 | `loader.KNOWN_DOC_TYPES` 와 `search.DOC_TYPE_ALIASES` 를 **함께** 갱신. 안 하면 API 가 400 을 낸다 |
| coverage 축 추가 | `loader.MATRIX_COLS` 는 5축 고정. 새 축은 `other_types` 로 답해진다 |
| 자재 커버리지 유형 추가 | `loader.BUNDLE_TYPES`(RoHS/REACH/PFAS/MSDS) |
| 새 제품군/모델 | 코드 변경 불필요. 단 2-3 의 사전 캐시를 비울 것 |
| KC 신규 등록 | KC manifest 의 `contents[]` 는 **파일명 기준**이다. 본문은 색인되지 않으므로 필증 번호 질의는 계속 "파일 확인" 안내 |
| 내부 메일 자료 추가(`추가자료_후보목록.csv`, 285모델·326종) | 매뉴얼·상세페이지는 `Manual` 유형으로 들어온다. **사용법 질의는 인증 경로가 아니라 legacy 경로에서 쓰는 것이 맞다** — 0단계 라우팅 표의 A 급에 `매뉴얼`을 넣을지 그때 재검토 |
